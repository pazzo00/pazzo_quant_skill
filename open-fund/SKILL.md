# 因子溢价、基金暴露与组合优化

在数据项目根目录执行脚本。脚本默认把当前工作目录作为项目根目录；也可用环境变量 `FACTOR_PREMIUM_PROJECT_ROOT` 显式指定。Skill 自带全部项目内 Python 辅助代码，但不内置行情、财报、基金数据或第三方库。

首次安装要求 Python 3.10 或更高版本，并运行 `python -m pip install -r "{SKILL_DIR}/requirements.txt"`。开源包内置的数据路径模板位于 `assets/factor_data_paths.example.json`；复制后填写实际路径，不要直接修改模板。

## 每次调用的强制前置步骤

每次使用本 skill，任何暴露、筛选、优化或回测之前，都先运行：

`python "{SKILL_DIR}/scripts/prepare_data.py" --target-end {本次截止日}`

该步骤依次检查并补齐 BAB 个股因子、补齐 QMJ 个股因子、再增量更新六因子溢价。不得因为已有 `premium.parquet` 就跳过；只有在同一任务中已经成功执行过 prepare，后续回测才可显式使用 `--skip-prepare`。

首次运行先验证默认路径和字段。若任何必需数据不存在、路径含义不明确或用户的数据结构与默认结构不同，停止计算并请用户提供路径映射；不要猜路径或静默换数据。路径 JSON 结构见 [references/workflow.md](references/workflow.md)。如果只是输出 BAB/QMJ 文件尚不存在，则由 prepare 创建，不需要询问。

## 工作流

完成 prepare 后，按用户需要运行以下一个或多个阶段：

1. 更新暴露：运行 `scripts/factor_pipeline.py exposures --codes ... --as-of ...`。默认同时维护 `capm`、`four_factor`、`six_factor` 三种模型；窗口从第 t 日向前取 n 个自然年，`--years` 默认 5。若提供 `--start-as-of` 和 `--frequency`，输出各调仓截面的滚动暴露。
2. 分位筛选：用户给标的及其因子值时，整理成每行一个标的的 CSV/Parquet，再运行 `scripts/factor_pipeline.py select`。默认选前 10% 或后 10%，数量按 `ceil(N × 10%)` 且至少 1 个；并列时按标的代码稳定排序。
3. 单期优化：运行 `scripts/optimize_portfolio.py`。把用户的自然语言目标映射成脚本支持的目标、约束和输入列；若目标无法准确映射，先说明数学表达式和必要假设，再扩展脚本或询问一个关键问题。
4. 滚动优化回测：运行 `scripts/backtest_portfolio.py`。严格使用用户指定的日、周、月、季或年调仓频率；每个调仓日只使用截至当日的数据，权重从下一交易日生效，并输出净值曲线、逐日收益、历次权重和指标摘要。
5. 选择与权重归因：用户要求判断优化价值来自“选了哪些标的”还是“如何分配权重”时，在滚动回测中启用 `--selection-weighting-comparison`。输出三条同口径曲线：原优化组合；原优化组合正权重持仓等权；筛选因子最优 N 只标的等权，其中 N 等于当期优化组合的实际持仓数。三组必须共用调仓日、生效日、收益数据和费用假设。

详细命令、输入结构和目标映射见 [references/workflow.md](references/workflow.md)。只有在执行相应阶段时才读取该参考。

## 不可破坏的口径

- 日收益使用复权价 `close × factor` 的百分比变化。
- 本 Skill 计算的是基于用户本地股票池的 Fama–French 风格因子，不是 Kenneth French 官方因子文件。`mkt_rtn` 当前为本地股票池市值加权市场收益；没有无风险利率输入时，不将其表述为严格的市场超额收益。
- Fama/UMD/QMJ 组合沿用项目现有口径：市值加权；SMB/HML 与 QMJ 使用 2×3 分组；UMD 使用两端 30%；BAB 使用 beta 中性化秩权重。
- 默认 `signal_lag=0` 以兼容已有历史文件。若用户要求可交易回测或避免收盘特征与当日收益同日使用，改为 `--signal-lag 1` 并明确记录口径变化。
- 暴露回归包含截距，只使用基金收益和全部所选因子都非空的完整日期；禁止把缺失因子填成 0。
- 三种模型固定为：CAPM=`mkt_rtn`；四因子=`mkt_rtn+smb+hml+umd`；六因子=四因子+`bab+qmj`。除非用户明确要求自定义，不混用模型名称与因子集合。
- 截止日不是交易日时，使用不晚于该日的最后共同交易日，并在结果中返回实际窗口终点。
- 默认最少 252 个完整观测；不足时不输出伪精确 beta，而是报告该标的失败原因。
- 用户只给候选标的时，不擅自再做分位筛选；用户给因子值并要求前/后 10% 时才筛选。
- “因子最优 N 只等权”必须沿用用户指定的筛选方向：前端筛选取因子最高 N 只，后端筛选取因子最低 N 只。N 由同一期优化组合中权重大于 `active_weight_tolerance` 的标的数量决定；默认阈值为 `1e-10`，并在结果中披露。
- 优化默认是多头、权重和为 1。未给单标的上限时使用 `max(1/N, min(20%, 2/N))`，并在交付中披露。不要把求解成功等同于未来表现保证。
- 回测必须是 walk-forward：筛选值、因子暴露、预期收益、风险矩阵和约束都只能使用调仓日当时可见的数据；调仓日计算的权重下一交易日生效。默认交易成本为 0；用户要求计费但未提供费率时，先用 `scripts/update_fund_fees.py` 搜索公开费率。对查不到的基金，申购费和赎回费分别使用本次已查到样本的平均值替代，输出中必须标记替代记录和费率查询日期，禁止静默按 0 处理。
- 基金净值已经扣除管理费、托管费和销售服务费时，不在净值回测中重复扣除这些持续性费用。基金交易费按买入金额扣申购费、卖出金额扣对应持有期的赎回费；若只做年度近似，可使用 365 天对应档位并明确披露。费率按单边权重变化计算，初始建仓也计费，期末未清仓则不虚构赎回费。

## 执行与交付

- prepare 先比较全部输入和输出日期。若目标日期晚于股票、市值、市场指数或财报数据可支持的共同终点，明确报告被哪个输入截断，并向用户索取更新后的路径或数据；不伪造缺失日期。
- 用户提供的原始因子值、候选池和当前权重只读；结果写到用户指定位置，未指定则写到 `fund_return_analysis/outputs/<截止日>/`。
- 溢价写入采用临时文件替换，避免中断造成半文件；不要删除旧输出。
- 优化后至少报告：入选标的、权重、目标值、预期收益（如适用）、年化波动率、组合因子暴露、约束余量、求解状态和全部默认假设。
- 回测后至少交付净值图、净值数据、历次权重、年化收益、年化波动、夏普、最大回撤、累计换手、调仓次数、基准定义、调仓频率和交易成本；使用基金级费率时还要交付费率明细、缺失替代比例和累计费用拖累。
- 启用选择与权重归因时，额外交付 `selection_weighting_comparison.png`、三线净值数据、两组等权基准的历次权重，以及三组的年化收益、波动、夏普、最大回撤和累计换手。解释时区分：优化组合与同持仓等权的差异主要反映配权效应；同持仓等权与因子最优 N 只等权的差异同时包含候选池内再选择和暴露控制效应，不把它误称为纯权重贡献。
- 先检查结果是否有限、权重和是否接近 1、上下界和因子约束是否满足，再交付。
